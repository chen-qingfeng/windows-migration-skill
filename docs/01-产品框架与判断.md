# 新旧电脑迁移工具 · 产品框架与判断

> 版本 v0.1 ｜ 2026-11 ｜ 面向"做一个 PC 换机迁移产品"的可行性梳理

---

## 0. 先给三句话

1. **用户要的不是"搬程序"，是"新电脑开机就能干活"。** 程序应该被重装，配置、数据、身份才应该被搬。把"程序搬运"当成核心，是这个想法最容易踩进去的坑。
2. **PC 上没有"手机搬家"，不是没人想到，是结构上做不成全量迁移。** 过去十五年至少有三代产品试过，包括微软自己。别在"全量克隆"这条路上和平台厂商 + 物理定律较劲。
3. **真正能成的切口是"高频重装的人"**：AI 工作者、开发者、一人多机的技术人。他们痛感最强、付费意愿最高、场景可验证、技术边界可控，而且这个群体正在变大。

---

## 1. 把问题拆对：一次换机到底在搬什么

绝大多数人一想到"搬家"，脑子里是"把旧电脑的东西整体搬过去"。但这个模糊的"东西"其实由三类完全不同的资产组成，迁移难度差了两个数量级：

| 资产类型 | 具体内容 | 迁移本质 | 难度 | 用户痛感 |
|---|---|---|---|---|
| **数据** | 文档、照片、下载、项目文件 | 文件复制 | ★☆☆☆☆ | 低（网盘/U盘/移动硬盘已解决大半） |
| **程序** | 应用本体、注册表、COM 组件、服务、驱动 | 系统状态复制 | ★★★★★ | 高（但要的是"能用"，不是"原件"） |
| **状态** | 配置、偏好、插件、密钥、登录态、许可、使用习惯 | 意图与身份迁移 | ★★★☆☆ | **最高**（这是真正让人抓狂的部分） |

**关键判断：用户的痛，90% 在第三类，而现有工具 90% 的工程量花在第二类。**

用户抱怨"又要重装一遍"，真正的潜台词是：

- 我不记得装过哪些软件了（**清单丢失**）
- 每个软件都要重新找安装包、点下一步、取消捆绑（**流程摩擦**）
- 装完还要重新登录、重新配置、重新装插件（**状态重建**）
- 有些软件我根本不知道当初怎么装上的（**知识丢失**）

所以产品的本质不是"传输工具"，是**"经验的外化与重放"**。

## 2. 为什么 PC 没有"手机搬家"：历史教训

### 2.1 手机为什么能做成

- **生态封闭**：iOS/Android 由一家公司定义数据模型，通讯录、相册、App 列表都是标准结构。
- **入口强制**：新机开机激活流程里就内置"从旧手机导入"，用户没有选择。
- **免费 + 预装**：厂商把它当获客手段，不指望它赚钱。
- **数据模型统一**：App 本身不迁移，只迁移"App 列表 + 账号"，重装由商店完成，天然规避了许可问题。

### 2.2 PC 为什么做不成

| 结构性原因 | 说明 |
|---|---|
| **生态开放且碎片化** | 应用来自 exe/msi/绿色版/商店/Steam/企业分发，没有统一清单 |
| **没有强制入口** | 用户自己装系统、自己装软件，没人能卡住这个流程 |
| **许可与盗版** | 搬"装好的程序"等于复制授权，法务上极其危险；正版软件又普遍硬件绑定 |
| **无利可图** | 换机是 3–5 年一次的低频事件，CAC 摊不平；预装方（整机厂）也没动力做重活 |
| **支持成本极高** | 迁移失败 = 用户数据风险 + 口碑崩塌，小团队扛不住 |
| **平台方随时能收走** | 见下节 |

### 2.3 已经有人试过，而且不止一次

- **Windows 轻松传送（Easy Transfer）**：Win7 时代的官方方案，Win8.1 起弃用，Win10 彻底移除。死于"跨版本应用状态不可迁移"。
- **微软 2025 年又试了一次**：据报道推出了支持局域网传输的新迁移工具，定位类似"轻松传送"的复活（[IT之家报道](https://m.ithome.com/html/0869764.htm)）。但实测反馈是"仍会留下不少东西不搬"（[XDA](https://www.xda-developers.com/new-windows-transfer-tool-leave-stuff-behind/)）。
- **更早的 Windows 备份/迁移功能**：据报道测试约一年后被弃用，理由是使用率过低（[相关报道](https://m.163.com/dy/article/L6PTHQU20511BLFD.html)）。
- **商业软件**：Laplink PCmover、Zinstall WinWin、EaseUS Todo PCTrans、AOMEI 等，活了十几年，始终是小众付费工具，没有出现"手机搬家"级别的产品（[EaseUS 迁移方案页](https://br.easeus.com/pc-transfer/movedor-de-pc-para-transferir-programas-para-novo-computador-windows.html)）。

**这一节的结论非常重要：**

> 这个赛道的空位，不是"没人发现的机会"，而是"被反复验证过的结构性难题"。
> 谁想进来，必须先回答："我凭什么能解决前三次失败的那个原因？"

如果你答不上来，那你做的只是第 N+1 个 PCmover。

### 2.4 但今天确实出现了三个新变量

这不是说旧结论失效，而是说**边界条件变了**：

1. **本地 AI 让"状态"变得又贵又重**。本地模型动辄几十 GB，Agent 配置（MCP、API Key、提示词库、记忆库）高度个人化且无云端同步。这是 2010 年不存在的资产类型。
2. **包管理器成熟**。winget / scoop / choco 让"声明式重装"第一次在 Windows 上变得可行——这是"不搬程序也能还原程序"的技术前提。
3. **一次被迫的换机潮**。Windows 10 已于 2025 年 10 月终止支持，加上 x64 → ARM64 的架构切换，未来两三年会有大量"不得不换"的用户。

## 3. 用户分层：先想清楚赚谁的钱

| 人群 | 换机/重装频率 | 痛感 | 付费意愿 | 技术可控性 | 判断 |
|---|---|---|---|---|---|
| **AI 工作者 / 独立开发者** | 高（1–2 年，甚至一年多次） | ★★★★★ | ★★★★☆ | ★★★★☆ | **首选切口** |
| 专业软件用户（设计/剪辑/财务/工控） | 中（3–5 年） | ★★★★★ | ★★★★☆ | ★★☆☆☆ | 痛但难做，许可复杂 |
| 中小企业 IT / 装机商 | 高（批量） | ★★★★☆ | ★★★★★（按台付） | ★★★★☆ | **第二增长曲线** |
| 游戏玩家 | 中 | ★★★☆☆ | ★★☆☆☆ | ★★★★☆ | Steam 库迁移已半解决 |
| 普通家庭用户 | 低（5 年+） | ★★★☆☆ | ★☆☆☆☆ | ★★☆☆☆ | 流量大、付费差、支持成本高 |

**建议：C 端切"AI/开发者"，B 端切"中小企业 IT 与装机服务商"。普通家庭用户只作为免费流量入口，不作为收入来源。**

理由：AI/开发者人群有三个别人没有的性质——他们**自己就在频繁重装**（试新模型、换环境、折腾工具链），他们**愿意为省时间付费**，而且他们**会写评测、会传播**。

## 4. 产品定位：搬"配置"，不搬"程序"

### 4.1 一句话定位

> **不是把旧电脑搬过来，是让新电脑在 30 分钟内回到你熟悉的样子。**

或者更锋利一点：

> **"我们不搬软件，我们搬你的使用习惯。"**

### 4.2 三层模型（整个产品的主干）

```
旧电脑                                     新电脑
┌──────────────┐                      ┌──────────────┐
│  ① 清单      │  扫描 → 指纹 → 打包  │  报告 + 计划  │
│  (Inventory) │ ───────────────────► │              │
└──────────────┘                      └──────┬───────┘
                                             │
┌──────────────┐   定义"怎么重装"     ┌──────▼───────┐
│  ② 重建      │ ◄─────────────────── │ 自动重装     │
│ (Reprovision)│   winget/scoop/msi   │ 静默参数     │
└──────────────┘                      └──────┬───────┘
                                             │
┌──────────────┐   配置/数据/密钥     ┌──────▼───────┐
│  ③ 状态      │ ───────────────────► │ 还原 + 校验  │
│  (State)     │   E2E 加密通道       │ 差异报告     │
└──────────────┘                      └──────────────┘
```

**核心设计原则：声明式重建（Declarative Reprovision），而不是块级复制（Block-level Clone）。**

- 旧电脑产出的是**一份描述**（"我有什么、怎么装的、配置在哪"），不是**一堆二进制**。
- 新电脑按描述**重新构建**，能装的自动装，装不了的生成清单让人处理。
- 这样天然规避了注册表、COM、驱动、许可、跨架构的一整片雷区。

### 4.3 明确的产品边界

| 做 | 不做 |
|---|---|
| 应用清单发现与归一化 | 系统盘克隆 / 整机镜像 |
| 声明式重装（包管理器优先） | 注册表级程序搬运 |
| 应用配置与数据迁移 | 驱动程序迁移 |
| AI Agent / 开发环境状态迁移 | 破解、绕过许可、搬"绿色版" |
| 大文件增量同步 | 云端备份存储服务 |
| 差异报告与人工引导 | 保证"100% 一模一样" |

最后一条尤其重要：**永远不要承诺 100%**。诚实地说"这 8 件事需要你自己做"，比假装全自动然后失败，口碑差一个数量级。

## 5. 技术架构

### 5.1 分层

```
┌─────────────────────────────────────────────────────────┐
│  UI 层：向导 / 进度 / 差异报告 / 人工处理清单            │
├─────────────────────────────────────────────────────────┤
│  编排层：迁移剧本引擎（Playbook Engine）                 │
│         依赖排序 · 失败重试 · 断点续做 · 回滚            │
├──────────────┬──────────────┬──────────────┬────────────┤
│ ① 采集       │ ② 归一化     │ ③ 传输       │ ④ 重建     │
│ Discovery    │ Normalize    │ Transport    │ Reprovision│
│              │              │              │            │
│ 注册表卸载项 │ 应用指纹     │ 局域网直连   │ winget     │
│ winget list  │ 来源判定     │ USB4/雷雳    │ scoop      │
│ scoop/choco  │ 可重装性     │ 云中转(可选) │ choco      │
│ Steam 库     │ 许可类型     │ 加密+校验    │ MSI/EXE    │
│ 开始菜单     │ 配置路径     │ 断点续传     │ 商店       │
│ 计划任务/服务│ 静默参数     │ 去重压缩     │ 手动引导   │
│ 环境变量     │              │              │            │
├──────────────┴──────────────┴──────────────┴────────────┤
│  ⑤ 状态层 State：配置目录 / dotfiles / 密钥 / 浏览器 / 字体 │
├─────────────────────────────────────────────────────────┤
│  ⑥ 校验层 Verify：清单比对 · 冒烟测试 · 差异报告         │
├─────────────────────────────────────────────────────────┤
│  ⑦ 安全层：本地优先 · E2E 加密 · 密钥不出设备 · 审计日志  │
└─────────────────────────────────────────────────────────┘
```

### 5.2 各层要点

**① 采集层（Discovery）**
Windows 上"装了什么"有至少七个真相来源，且互相不一致，必须交叉验证：

- 注册表 `Uninstall` 键（含 HKLM 32/64 位视图、HKCU）
- `winget list` / `scoop list` / `choco list`
- 开始菜单快捷方式（能发现绿色版）
- 服务与计划任务（能发现无 UI 的后台组件）
- Steam / Epic / 战网库清单
- 浏览器扩展
- 环境变量 PATH、已注册的文件关联

**② 归一化层（Normalize）—— 这是产品的大脑**

把"一个装过的东西"变成一条结构化记录：

```json
{
  "id": "com.example.app",
  "display_name": "示例应用",
  "version": "2.3.1",
  "source": "winget",
  "package_id": "Example.App",
  "arch": "x64",
  "install_location": "C:\\Program Files\\Example",
  "license_type": "perpetual_machine_bound",
  "silent_install": { "args": ["/S", "/D=C:\\Program Files\\Example"] },
  "config_paths": ["%APPDATA%\\Example", "%LOCALAPPDATA%\\Example"],
  "requires_relogin": true,
  "post_install_steps": ["登录账号", "重新激活许可"],
  "confidence": 0.92
}
```

`confidence` 字段是灵魂：0.92 表示"我知道怎么装它"，0.3 表示"我只能告诉你它存在"。UI 上要如实呈现这个分数，而不是假装都懂。

**③ 传输层（Transport）**

- **优先局域网直连**：mDNS 发现 + QUIC/TCP，2.5GbE 下可达 200–280 MB/s，Wi-Fi 7 下 100 MB/s+。
- **次选 USB4/雷雳直连**（40–80 Gbps），适合几十 GB 的模型文件。
- **云中转只做"小状态"**（配置、清单、密钥密文），永远不做大文件——成本受不了。
- **加密**：传输层用 TLS 1.3 + 应用层 age/libsodium；配对用短码 + 设备指纹双向确认，防中间人。
- **断点续传 + 内容寻址去重**（类似 restic/borg 的 chunk 化），同一台机器重复迁移只传增量。

**④ 重建层（Reprovision）**

按"确定性从高到低"排序执行，最大化自动完成率：

1. winget / scoop / choco 有包的 → 全自动
2. MSI 有静默参数的 → 自动（参数从配方库取）
3. 有官方静默安装包的 EXE → 自动下载安装
4. 只能手动 → 生成带下载链接和步骤的引导卡片
5. 无法重装（绿色版、内部工具）→ 标记为"需要你手动处理"，可打包原始目录

**⑤ 状态层（State）**

这是差异化所在，也是最需要"配方库"的地方：

- 配置文件目录（`%APPDATA%`、`%LOCALAPPDATA%`、`~/.config`）
- dotfiles（`.gitconfig`、`.ssh`、`.npmrc`、`.zshrc`、PowerShell profile）
- 浏览器 profile（书签、扩展、密码库需重新授权）
- 字体、输入法词库
- **AI Agent 状态**（见 5.3）
- 开发环境：WSL 发行版 vhdx、Docker 镜像、conda 环境（后两者建议重建而非搬运）

**⑥ 校验层（Verify）**

迁移完必须给一份"体检报告"：

- 清单比对：应装 N 个，实装 M 个，缺哪些
- 冒烟测试：关键应用能否启动、版本是否匹配
- 配置抽检：配置文件是否到位、大小是否合理
- **人工待办清单**：按优先级排好的 5–10 件事

**⑦ 安全模型（生死线）**

一个搬家工具天然拥有最高权限，一旦被攻破就是供应链攻击。必须：

- **本地优先**：默认不经过任何服务器，能直连就直连
- **密钥零上传**：API Key、Token 只在两台设备间加密直传，服务端永不接触
- **最小权限**：默认不请求管理员权限，需要时逐项申请
- **可审计**：每一步操作写本地日志，用户可查
- **代码签名**：EV 证书，这既是安全也是杀软白名单的前提

### 5.3 AI Agent 场景：最值得先做的"配方"

这是 2010 年不存在、2026 年最痛的一块。典型资产（路径随版本变化，需实测校准）：

| 资产 | 典型位置 | 迁移方式 |
|---|---|---|
| Claude Desktop（含 MCP 配置） | `%APPDATA%\Claude\claude_desktop_config.json` | 直接搬 + 提示重登 |
| Cursor 配置与扩展 | `%APPDATA%\Cursor\User\` | 直接搬 |
| VS Code 配置 | `%APPDATA%\Code\User\` | 搬（也可用内置同步） |
| Ollama 本地模型 | `%USERPROFILE%\.ollama\models` | 大文件增量同步 |
| LM Studio 模型 | `%USERPROFILE%\.lmstudio\` 等 | 大文件增量同步 |
| ComfyUI | `models/`、`custom_nodes/`、工作流 | 目录搬 + 依赖重装 |
| API Key / `.env` | 散落各处 | 加密收集，生成清单让用户确认 |
| SSH / GPG 密钥 | `%USERPROFILE%\.ssh`、`%APPDATA%\gnupg` | 加密搬 + 权限修复 |
| WSL 发行版 | `%LOCALAPPDATA%\Packages\...\LocalState\ext4.vhdx` | vhdx 整体搬 |
| 提示词库 / 记忆库 | 各工具私有格式 | 按配方逐项处理 |

**这一块的战略意义：这是唯一一块"云端账号解决不了"的迁移需求。** 越是本地优先的工具，越需要搬家工具。

## 6. 硬骨头：这些坑必须提前想明白

| # | 难点 | 为什么难 | 解法 | 进 MVP？ |
|---|---|---|---|---|
| 1 | **DPAPI 凭据不可迁移** | Windows 凭据管理器用机器/用户绑定的密钥加密，换机必失效 | 不做搬运，只做"待重登清单" | ✅ 只出清单 |
| 2 | **硬件绑定许可** | Adobe、Office、专业软件绑定主板/TPM | 建"反激活 → 新机激活"的流程配方 | ⚠️ 只给指引 |
| 3 | **注册表 COM / 服务注册** | 手工搬注册表是灾难，且极易搞坏新系统 | 一律重装，不碰注册表 | ✅ 明确不做 |
| 4 | **x64 → ARM64** | 部分应用无 ARM 版 | 建"ARM 可用性"字段，给替代建议 | ⚠️ v2 |
| 5 | **大文件** | 本地模型、WSL vhdx、Steam 库动辄 50–500 GB | 内容寻址去重 + 增量 + 断点续传 | ✅ 必须 |
| 6 | **杀软误报** | 国内 360/火绒/管家对"读写大量文件 + 提权"极度敏感 | EV 签名 + 提前报备 + 白名单申请 | ✅ 必须 |
| 7 | **中文路径 / 长路径 / 权限** | 260 字符限制、ACL 继承、OneDrive 占位文件 | 统一走 `\\?\` 前缀，跳过 reparse point | ✅ 必须 |
| 8 | **账号即状态** | 越来越多软件状态在云端，本地无物可搬 | 产品叙事从"搬数据"转向"重建工作台" | ✅ 定位层 |
| 9 | **迁移中断 / 回滚** | 搬到一半失败，用户处于"两台都不能用"状态 | 幂等设计 + 每步可回滚 + 断点续做 | ✅ 必须 |

## 7. MVP 该做什么

### 7.1 MVP 定义（建议 8–10 周）

> **在一根网线/U 盘的前提下，30 分钟内完成：应用清单迁移 + 配置迁移 + 大文件迁移，并交付一份"你需要手动做的 7 件事"清单。**

必须包含：

1. 只读扫描器（输出完整清单 + 可迁移性评分）
2. 局域网直连传输（加密、断点续传）
3. 前 100 个高频应用的配方（覆盖 80% 装机量）
4. winget/scoop 自动重装
5. 配置目录与 dotfiles 迁移
6. 迁移后差异报告
7. 本地大文件增量同步

坚决不做：系统克隆、注册表搬运、驱动迁移、云备份、跨平台（macOS）。

### 7.2 成功指标

| 指标 | 目标 | 为什么是它 |
|---|---|---|
| **自动完成率** | ≥ 70% 的应用无需人工 | 决定体验下限 |
| **人工待办数** | ≤ 10 项 | 超过 10 项用户就放弃 |
| **迁移后 7 天内回开旧机** | ≤ 20% 的用户 | **最硬的核心指标**——真正验证"搬完了" |
| 端到端耗时 | ≤ 30 分钟（不含大文件） | 心理阈值 |
| 失败可恢复率 | 100% | 一次数据事故 = 产品死亡 |

第三个指标最值得盯：如果用户一周内还得回去开旧电脑，说明迁移根本没完成，其他指标都是自欺欺人。

## 8. 护城河：应用配方库

这是我认为**唯一真正可积累的资产**，也是回答"你凭什么做成第四次"的答案。

### 8.1 它是什么

几千到几万个应用的"迁移配方"：

```
应用 → 包管理器 ID → 静默安装参数 → 配置路径 →
       需不需要重登 → 许可怎么转移 → 跨架构可用性 →
       已知坑 → 迁移后的验证方法
```

### 8.2 为什么它是护城河

- **有网络效应**：用户越多，配方越准；配方越准，用户越多。
- **有数据壁垒**：这不是爬虫能抓的，必须靠"装一遍、试一遍"积累。
- **有迁移成本**：竞品要复制，得重走一遍同样的苦活。
- **可复用**：同一份配方同时服务 C 端迁移、B 端批量部署、装机商工具。

### 8.3 冷启动

1. 从 winget / scoop / choco 的 manifest 里自动抽取安装参数（免费拿到几千条）
2. 用"安装前后文件系统快照 diff"自动推断配置路径（可批量跑虚拟机）
3. 社区贡献 + 用户端"这次迁移有问题"的反向反馈
4. 优先覆盖：开发者工具、AI 工具、浏览器、办公、输入法、常用国产软件

**这件事的正确做法：第一版就把配方库设计成可外部贡献的格式（类似 Homebrew Cask 的 tap），从第一天起就在攒资产。**

## 9. 商业模式

换机是低频事件，这决定了**C 端订阅制基本不成立**。可行的组合：

| 模式 | 定价 | 说明 |
|---|---|---|
| **免费扫描器** | ¥0 | 只出清单和报告，零风险引流，也是最好的需求验证器 |
| **C 端一次性买断** | ¥99–199 / 次 | 换机时买一次，心理账户合理 |
| **C 端"年度保险"** | ¥49/年 | 不限次数 + 多机同步 + 配置云同步（轻量） |
| **B 端按台** | ¥30–80 / 台 | 企业批量换机、IT 外包、装机店，**这才是真钱** |
| **硬件/渠道捆绑** | 分成 | 整机厂、装机店、系统重装工具、NAS 厂商 |

**反模式（不要做）：**

- ❌ C 端订阅制（用户一年用一次，第二年必退订，还会骂）
- ❌ 自建云存储（成本无底洞，且和"本地优先"的信任叙事冲突）
- ❌ 靠"搬盗版软件"获客（法律风险 + 品牌自杀）
- ❌ 免费版阉割到不可用（迁移是"全有或全无"的体验，阉割等于没做）

## 10. 风险清单

| 风险 | 等级 | 说明 | 应对 |
|---|---|---|---|
| **法律：许可与盗版** | 🔴 最高 | 搬运已安装程序 = 复制授权；协助"绿色版"迁移可能构成帮助侵权 | 只做"重装"，永不复制已安装二进制；配方库只存公开安装参数 |
| **安全：供应链攻击** | 🔴 最高 | 搬家工具是最佳攻击载体，一旦出事全盘皆输 | 开源核心、代码签名、最小权限、第三方审计 |
| **平台：微软自己做** | 🟠 高 | 微软已两次尝试迁移工具，随时可能再收走 | 只做微软"不愿做/做不好"的部分：第三方应用配方、AI/开发环境、本地大文件 |
| **信任：用户不给密码** | 🟠 高 | 陌生小工具要求高权限，天然被怀疑 | 本地优先、开源、可审计、绝不碰密码 |
| **支持成本** | 🟠 高 | 迁移失败的用户情绪极差，客服成本高 | 幂等 + 回滚 + 诚实的预期管理 |
| **低频导致增长难** | 🟡 中 | 用户换完机就卸载了 | 用"重装系统""多机同步""环境复制"做高频场景 |
| **杀软误报** | 🟡 中 | 国内安全软件拦截率高 | EV 证书 + 白名单 + 分步提权 |

**关于"微软威胁"，要给一个更精确的判断：**

微软做迁移工具，永远会止步于"文件 + 系统设置 + 商店应用 + OneDrive"。它**不会**去维护一个几万条的第三方应用配方库，也**不会**去搬 Ollama 模型和 MCP 配置。这不是能力问题，是商业动机问题——微软要推的是 OneDrive 和 Microsoft Store，不是帮你留住 Adobe 和绿色版工具。

所以**你的生存空间恰恰是微软的战略盲区**。但前提是：你必须在微软"顺手就能做"的范围内保持轻，在它"不愿意做"的范围内扎深。

## 12. 动手之前，先做五个验证

成本极低，信息量极大：

1. **访谈 20 个近一年换过电脑的人**，只问三个问题：重装花了多久？最烦哪一步？最后悔没提前做什么？
   → 如果答案集中在"配置和登录"，切口成立；如果集中在"文件拷得慢"，那这生意该做成传输工具。
2. **做一个只读扫描器**（1–2 周），输出"你的电脑上有 143 个可迁移项，其中 96 个可自动完成"。
   → 这个报告本身就是最好的营销素材。
3. **发一篇内容**：《我统计了 100 台电脑的软件清单，发现了这些规律》。
   → 在 V2EX / 少数派 / 小红书 / X 上测真实转化。
4. **手动帮 5 个人做一次迁移**（人肉 MVP），全程录屏计时。
   → 你会发现自己对"配方"的假设有多少是错的。
5. **算一笔账**：一个用户从看到广告到完成付费，CAC 多少？换机频率 4 年一次，LTV 就是一次买断（¥150），CAC 必须 < ¥50。
   → 如果算不过来，说明必须走 B 端或渠道。

## 13. 十条直白意见

1. **别做"一键"。** "一键"是营销词，不是产品设计。诚实的"自动 80% + 引导 20%"，比虚假的"一键全自动"活得久得多。
2. **别碰系统克隆。** 那是 Ghost/傲梅/ diskgenius 的地盘，红海、低毛利、全是价格战。
3. **把"清单"当产品，别当中间产物。** 用户最缺的是"我到底装过什么"这个知识。一份漂亮的清单本身就值钱。
4. **配方库是唯一的护城河。** 第一行代码就该为它设计数据结构，第一天就该允许外部贡献。
5. **选 AI/开发者做第一批用户。** 他们痛、他们有钱、他们会传播、他们的环境最"不可复制"。
6. **把"人工待办清单"做成招牌功能而不是遮羞布。** 敢明说"这 7 件事得你自己做"的产品，反而更可信。
7. **本地优先是信仰也是策略。** 任何要求上传密钥的设计，都会在第一时间杀死转化率。
8. **低频是诅咒，要用场景破解。** 重装系统、公司换机、多机同步、环境复制——这四个场景的频率都远高于"换电脑"。
9. **警惕微软，但别怕微软。** 它做"通用"，你做"深水区"；它要推云，你要保本地。战略上错位，战术上共存。
10. **先卖给装机店，再卖给个人。** B 端的付费决策快、单价高、还能带来真实场景数据，比在 C 端和"免费"搏斗高效得多。
