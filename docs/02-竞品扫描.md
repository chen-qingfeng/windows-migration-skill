## 0. 先定义"你的设想"包含哪些能力点

后面所有对比都用这 8 个编号：

| 编号 | 能力点 | 说明 |
|---|---|---|
| ① | **跨机传输** | 两台电脑之间直连/局域网把东西送过去 |
| ② | **自动发现** | 不用用户回忆，自动列出"这台机器装了什么" |
| ③ | **自动重建/迁移应用** | 不用手动找安装包、点下一步 |
| ④ | **配置随行** | 应用设置、个人偏好、插件、快捷键跟着走 |
| ⑤ | **身份与许可** | 登录态、凭据、激活状态的处理 |
| ⑥ | **大文件迁移** | 本地模型、虚拟机磁盘、游戏库 |
| ⑦ | **校验与差异报告** | 搬完告诉用户"还差什么" |
| ⑧ | **AI Agent 状态** | MCP 配置、提示词库、Agent 记忆、本地模型 |

判定标准：**达到**=核心流程与你的设想一致；**超过**=在该维度上比你的设想更成熟/覆盖更广；**接近**=只覆盖其中一两个点；**不如**=只沾边。

## 1. 结论先行

1. **你的设想在"分片"层面全部被人做过，而且有几片做得非常好。** 清单发现（winget）、批量重装（Scoop/Chocolatey/Ninite）、配置迁移（chezmoi/mackup）、声明式重建（Nix/home-manager）——每一片都有上万星的成熟项目。
2. **在"组合"层面（一台旧机 → 一台新机、一条流程、带验收），国内已经有一款免费产品：360 换机助手。** 它免费、走局域网、验证码配对、可选择软件并连同"软件配置、登录账号信息"一起搬。**功能覆盖上，它基本达到了你设想的前 5 点。**
3. **但它的路线是"搬二进制"，这正是它口碑崩掉的原因**——小红书上有明确的"换机助手不要用！！避雷"贴。这给你留了缝，但缝不在"能不能搬"，而在"搬得对不对"。
4. **国外商业产品（PCmover / Zinstall / EaseUS）功能上确实超过你的设想**——它们做的是真正的程序迁移（含注册表），但全是**一机一码、按机计费、闭源、且脆弱**。按你的口径，它们只作参考，不作对标。
5. **最重要的行业信号：微软自己做过，然后彻底放弃了。** Windows 11 的 PC-to-PC 迁移功能 2025 年初开始测试、2025 年 6 月推给 24H2 正式版，2026 年 9 月 13 日在预览版中正式停用，官方只留一句"PC 到 PC 迁移不再可用"，未解释原因（[中关村在线，2026-09-14](https://pc.zol.com.cn/1246/12467700.html)）。

**一句话总判断：你的设想没有被"完整实现"，但被"部分实现"了很多次；真正的空位不是功能，是"以重装为内核的那套组合 + 可验收的迁移结果"。**

## 2. 竞品地图：七个层级

```
┌─ L0 系统自带 ────────── Windows 备份(OneDrive) / PC-to-PC迁移(已下线) / 轻松传送(已死)
├─ L1 商业全量迁移 ────── PCmover / Zinstall / EaseUS Todo PCTrans / Dell Migrate   ← 一机一码
├─ L2 OEM 预装 ────────── 联想乐换机 / 各品牌迁移助手
├─ L3 国内消费级免费 ──── 360换机助手 / 各类"换机助手"下载站马甲
├─ L4 包管理与清单 ────── winget / Scoop / Chocolatey / UniGetUI / Ninite / PatchMyPC
├─ L5 配置与 dotfiles ─── chezmoi / mackup / yadm / dotter / rotz
├─ L6 声明式环境 ──────── Nix / home-manager / devbox / devenv        ← "不迁移"的解法
└─ L7 AI 配置同步 ─────── ai-setup / dsh-config-manager / vsync / mcp-config-manager ...
```

一条重要旁证：**苹果的迁移助理能做到"整机搬 + 应用重装 + 设置保留"，是因为生态封闭。** PC 上没有这个前提，所以"全量搬"此路不通，"清单 + 重装 + 状态"才是唯一可持续的路径——这恰好就是你的设想里最有价值的那一半。

## 6. 三个真空地带（也是你的机会）

### 真空一：以"重装"为内核的组合，没人产品化
所有"清单→重装→配置→校验"的积木都现成（winget/Scoop/chezmoi），但**没有一个人把它们缝成一条面向普通用户的流水线**。开源项目全是 0–1 星的个人脚本，商业项目全走"搬二进制"的旧路。

### 真空二：AI / 本地模型 / Agent 运行时，完全没人做
- `ai-setup` 只同步"配置文件"，不管装、不管模型、不管依赖。
- `MigrateOllamaModels` 只搬模型目录，不管其他。
- **没有任何工具能回答："我的 Cursor + Claude Desktop + Ollama + ComfyUI + WSL 这一整套，怎么在新机器上原样跑起来？"**

这是你设想里最新、最没人占的一块，也是唯一"云端账号解决不了"的一块。

### 真空三：迁移后的"验收"
所有产品都在"搬"字上做文章，没有一家在"搬完确认"上做文章。用户最恐惧的不是慢，是"不知道还差什么"。**一份"你现在还缺这 7 件事"的报告，是零成本的高价值差异化。**

### 附赠真空四：B 端批量
PCmover 卖 Technician License 给服务商，说明这个需求真实存在，但没有轻量的、按台计费的、面向中小企业的现代产品。

## 7. 关键问题：360 免费做完了，你还有机会吗？

有，但要看清它为什么"做完了却没做好"：

| 360 换机助手的问题 | 你的机会 |
|---|---|
| 走"搬二进制"路线 → 现代应用（Electron、商店应用、依赖运行库的软件）极易搬坏 | 走"重装"路线，天然兼容 |
| 黑箱：搬完不告诉你缺什么，失败了也不知道为什么 | 校验报告 + 人工待办清单 |
| 绑定 360 生态、推广弹窗、信任度低 | 纯净、开源、本地优先 |
| 不懂 AI / 开发环境 / 本地模型 | 这就是你的主战场 |
| 大厂 KPI 产品，随时可能停更（参考微软） | 小而专，能持续迭代 |

**你的差异化不是"我也能搬"，而是"我搬得对、搬得干净、搬完能验收"。**

## 8. 对"一机一码"的两层处理建议

**第一层：目标软件侧（你说要排除的那类）**

- 一机一码的软件（专业软件、行业软件、按硬件绑定的商业授权）**不要试图迁移**：
  - 技术上，搬过去也激活不了；
  - 法律上，绕过授权 = 侵权，产品的法律风险会瞬间从"低"跳到"高"。
- 正确做法：把它变成**"许可转移指引"**——告诉用户"这个软件需要先在旧机反激活，再到新机用你的账号重新激活"，并给出该软件的官方反激活入口。这既是合规，也是产品诚实度。
- **反过来说，排除掉一机一码之后，剩下的 80%（免费软件、开源工具、商店应用、包管理器软件、自建环境）恰恰是"声明式重装"最擅长的部分。** 你的设想在剔除这块之后，反而更成立了。

**第二层：竞品/商业模式侧**

- C 端一机一码 = 死路。换机 3–5 年一次，用户不会为"一次性事件"反复付费，且一机一码意味着口碑传播时"我朋友用不了"。
- B 端按台计费 = 活路。企业换机是批量、有预算、有 IT 负责人，且愿意为"可审计的迁移报告"付钱。

## 9. 建议你接下来做的三件事

1. **亲手跑一遍 360 换机助手**（30 分钟）：拿两台机器，装 20 个常用软件（含 Cursor、Ollama、微信、一个绿色版工具），看它搬完到底有几个能用。**这份实测报告会直接决定你的产品定义。**
2. **实测 PCmover 的试用版**（官方提供免费评估）：看"真正的程序迁移"在 2026 年到底能做到什么程度，尤其是 Electron 应用和商店应用。
3. **把"真空二"做成一个 demo**：写一个脚本，把 Cursor + Claude Desktop + Ollama + WSL 的配置和模型从 A 机搬到 B 机，录屏。**这个 demo 比任何商业计划书都有说服力。**

---

## 10. 一句话总结

> 你想做的事，**单点全被做过，组合只被做砸过**。
> 免费的那个（360）路线错了，收费的那些（PCmover）模式错了，微软那个（PC-to-PC）干脆放弃了。
> 剩下的位置很清楚：**用"重装"代替"复制"，用"验收"代替"承诺"，先把 AI/开发环境这块没人碰的硬骨头啃下来。**
