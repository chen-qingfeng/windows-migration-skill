## Stage 1 · v0.2 — 把规则从"文字"变成"数据"（约 2 周）

### 问题

现在分类规则只存在于 `SKILL.md` 的散文里，由 LLM 现场执行。后果：

- 同一份清单跑两次，结果可能不一样
- 改了规则，不知道是变好还是变坏
- 没法回归测试，也没法比较不同版本的准确率

### 交付

```
rules/classify.json      ← 排除名单、许可关键词、厂商组件、原因码，全部是数据
scripts/classify.ps1     ← 读 rules，输出 profile.json（PS 5.1 兼容）
evals/cases/*.json       ← 3–5 份脱敏机器快照
evals/expected/*.json    ← 期望结果
evals/run.ps1            ← 跑分类、比对、打印准确率
```

### 验收

- 同一份 `profile.raw.json` 跑十次，输出字节级一致
- 改一条规则，eval 分数会变，且能解释为什么变

### 为什么排第一

**没有它，后面每一步都是盲改。** 这也是"评测就是护城河"这句话的落地方式——
模型能力是公共的，但"它在真实场景里靠不靠谱"只有跑过的人知道。

## Stage 2 · v0.3 — 从"清单"到"计划"（约 2–3 周）

### 交付

`plan.ps1` 吃 `profile.json`，吐两样东西：

| 产物 | 给谁 | 内容 |
|---|---|---|
| `restore.md` | 人 | 三张表：一条命令能装的 / 要手动点的 / 别动 |
| `restore.ps1` | 机器 | 可执行的还原脚本（**只生成，不执行**） |

同时增加"目标机器画像"：架构（x64/ARM64）、已装软件、剩余空间——用来判断"这台装不装得下、旧不旧"。

### 验收

在干净的 Windows 虚拟机上，生成的脚本能装回 **≥70%** 的 `auto` 项。

### 注意

**整个 v0.3 依然零写入。** 它只产出文本，不碰系统。

---

## Stage 3 · v0.4 — 安全网（约 4–6 周，核心差异化）

### 交付

- VHDX 差分子盘 / 系统快照
- `apply.ps1`：默认 `dry-run`，只有显式 `--apply` 才写
- 任意一步失败都能回滚，**回滚耗时 < 60 秒**

### 验收

迁移跑到一半强行 kill，回滚后系统状态哈希与开始时一致。

### 为什么这一步最值钱

360 直接在你的机器上搬，PCmover 直接搬，微软试过又下线了。
**"敢让工具动手"的前提是"搞坏了能一秒退回去"**——这是唯一能撑起收费的东西，也是唯一没人做的。

## Stage 4 · v0.5 — 两台机器（约 3–4 周）

局域网直连、加密传输、断点续传、内容去重。

**只搬"大文件 + 配置"，不搬程序。** 程序永远走重装。

---

## Stage 5 · v0.6 — 垂直配方（长期，不设截止）

Cursor / Claude Desktop / Ollama / WSL / ComfyUI / Codex——每个一条配方：

- 怎么装（包管理器 ID 或官方安装器）
- 配置在哪（路径 + 已知版本差异）
- 哪几步必须人工（登录、授权、反激活）
- 装完怎么验证

**这是唯一能形成"搞 AI 的人换电脑就用它"这种心智的东西。**
也是唯一一块"云端账号解决不了"的需求。

## 横向：分发形态（并行，成本低）

同一个仓库，多种加载方式：

| 形态 | 用户怎么用 |
|---|---|
| Claude Code skill | 直接引用 `SKILL.md` |
| Codex / Cursor | 贴同一条 prompt |
| MCP server | 工具化调用（后续） |
| 纯命令行 | 不装 Agent 也能跑脚本 |

---

## 三条现在就要定的架构决策

| 决策 | 建议 | 理由 |
|---|---|---|
| **规则存哪** | 数据文件 `rules/classify.json` | Agent 和脚本读同一份，永远不打架 |
| **分类器用什么写** | PowerShell **5.1 兼容子集** | Windows 零依赖；macOS 装 pwsh 也能跑；不用引入 Node/Python |
| **报告谁渲染** | 脚本出数据，Agent 润色 | 但必须保证**纯脚本也能出一份能看的报告**，否则 Agent 一挂全挂 |

---

## 什么时候该停

写死在路线图里，比事后找理由诚实：

| 门 | 条件 | 不达标怎么办 |
|---|---|---|
| v0.2 → v0.3 | eval 准确率 < 90% | **停**，回去修规则，别做计划器 |
| v0.3 → v0.4 | 还原率 < 50% | **停**，清单都不准，安全网没意义 |
| v0.4 之前 | 没有 50 份真实用户报告 | **别做**，安全网很贵，先证明有人用 |

---

## 一句话

> **先把规则变成可测量的（v0.2），再让它能生成计划（v0.3），再让计划敢被执行（v0.4）。**
>
> 顺序反了——先做"一键迁移"——就是大多数同类产品死掉的方式。
